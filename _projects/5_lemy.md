## 문제 — 장판 오브젝트가 많아질 때 발생하는 프레임 저하

Lemy는 2D 탑뷰 액션 게임입니다. 몬스터와 장판 오브젝트가 동시에 많이 등장하는 상황에서 프레임 성능이 저하되는 문제가 있었습니다.

기존 오브젝트 처리는 GC를 줄이기 위해 오브젝트 풀을 사용하고 `GameObject`, `Collider2D`, `OnTriggerStay2D`와 같은 Unity 제공 컴포넌트 및 메서드에 의존했습니다. 짧은 시간에 오브젝트 수가 늘어날수록 풀링을 활용한 GC 제어만으로는 성능 문제를 충분히 해결하기 어려웠습니다.

## 접근 — 오브젝트 중심 처리에서 데이터 중심 처리로

- **필요한 상태만 데이터로 관리:** 위치와 지속 시간 등 처리에 필요한 정보를 구조체로 관리했습니다. 개별 `GameObject`를 생성하고 관리하는 방식에서 벗어나, 대량의 장판을 처리할 때 오브젝트 관리 부담을 줄이도록 설계했습니다.
- **충돌 판정 단순화:** 2D Collider 대신 거리 제곱(`sqrMagnitude`)을 이용해 오브젝트와 대상 사이의 거리를 직접 비교했습니다.
- **시각 효과 처리 분리:** 개별 오브젝트를 사용하는 방식 대신 `ParticleSystem.Emit`으로 시각 효과를 처리했습니다. 별도의 시각 효과 오브젝트를 관리하는 부담을 줄이고, Unity Particle System의 파티클 렌더링 방식을 활용하고자 했습니다.

이렇게 오브젝트의 게임 로직과 시각 효과를 분리하고, 대량의 오브젝트를 처리할 때 필요한 계산과 상태 관리에 집중하도록 구조를 변경했습니다.

## 결과 — 프로파일링에서 확인한 성능 변화

동일한 테스트 환경에서 구조 변경 전후의 성능을 측정했습니다.

| 측정 항목 | 변경 전 | 변경 후 | 변화 |
|---|---:|---:|---:|
| Physics2D 처리 시간(평균) | 6.41 ms | 2.55 ms | 약 60.2% 감소 |
| 전체 프레임 시간(평균) | 40.02 ms | 31.73 ms | 약 20.7% 감소 |
| GC Alloc(평균) | 34.59 KB | 28.17 KB | 약 18.6% 감소 |

Physics2D 처리 시간뿐 아니라 전체 프레임 시간과 GC Alloc도 감소했습니다. 측정 결과를 통해 변경 이후 물리 처리 시간과 전체 프레임 시간, 메모리 할당 지표가 함께 개선되었음을 확인했습니다.

## 나의 기여

팀 프로젝트에서 **기존 오브젝트 대량 생성 구조의 문제점을 분석하고, 데이터 기반 관리와 직접 거리 판정을 적용했으며, 시각 효과 처리 방식을 변경하고 프로파일러 수치로 변경 전후를 비교**했습니다.

## 배운 점과 후속 과제

이번 작업을 통해 오브젝트 풀링과 같은 일반적인 최적화 기법도 실제 병목에 따라 효과가 달라질 수 있음을 배웠습니다. 또한 객체 단위로 상태와 동작을 관리하는 방식만 고집하기보다, 대량으로 처리되는 데이터의 특성과 Unity의 물리·렌더링 구조를 함께 고려해야 한다는 점을 알게 되었습니다. 프로파일링으로 병목을 확인하고, 적절한 자료 구조와 처리 방식을 탐색해 적용하는 경험을 쌓았습니다.

이 페이지는 제가 담당한 기술 작업과 측정 결과를 중심으로 정리했습니다. 프로젝트 소유권과 팀 애셋의 공개 범위를 고려해 이미지와 소스 코드는 포함하지 않았습니다.
